# 🗾 Tokyo Life Blog (가칭)

**Java · Spring Boot · Spring MVC · MyBatis · PostgreSQL 기반 여행·생활 블로그**

도쿄에 거주하는 외국인의 시선으로 일본 여행과 생활 정보를 공유하는 한국어 블로그입니다.
직접 방문한 장소와 생활 경험을 글과 사진으로 기록하고, 실제로 배포하여 운영하는 것을 목표로 합니다.

> 현재 상태: 요건정의 초안 작성 단계. 아래 기능과 기술 구성은 구현 계획이며, 구현·테스트·배포는 아직 진행하지 않았습니다.

## 프로젝트 목적

- 직접 작성한 여행·생활 콘텐츠를 지속적으로 공개하고 운영합니다.
- Java MVC 기반 웹 애플리케이션의 요건정의, DB 설계, 구현, 테스트, 배포를 경험합니다.
- 기존 Java 코드와 SQL을 분석하고 검증한 경험을 직접 기능을 설계·개발하는 역량으로 확장합니다.
- 설계 이유, 오류 해결 과정, 운영 후 개선 내용을 기록합니다.

## 대상 사용자

- 방문자: 일본 여행과 생활에 관심 있는 한국어 사용자. 회원가입 없이 콘텐츠를 조회합니다.
- 관리자: 블로그 운영자 1명. 로그인 후 콘텐츠를 관리합니다.

## 첫 출시 기능 — 계획

- 최신 글, 글 목록·상세, 카테고리·태그별 조회
- 제목·본문 검색과 페이지 이동
- 운영자 소개, 모바일 대응 화면
- 관리자 로그인·로그아웃
- 게시글 작성·수정·삭제, 임시저장·미리보기·공개·공개 취소
- 사진 업로드·삭제·정렬, 대표 이미지 지정
- 카테고리·태그 관리

독자 회원가입, 댓글, 좋아요, 일본어 번역, 상품·주문·결제는 첫 출시 범위에 포함하지 않습니다.

## 기술 구성 — 제안, 환경 구성 시 확정

| 영역 | 후보 | 목적 |
| --- | --- | --- |
| 언어 | Java 21 | Java 기반 기능 구현 |
| 서버 | Spring Boot, Spring MVC | 서버에서 HTML을 생성하는 MVC 구조 |
| 화면 | Thymeleaf, HTML, CSS, JavaScript | 콘텐츠 표시와 관리자 입력 화면 |
| DB 접근 | MyBatis | SQL 직접 작성과 매핑 |
| DB | PostgreSQL | 관계 설계, 제약조건, 트랜잭션 |
| 인증 | Spring Security, 세션 | 관리자 인증·인가 |
| 테스트 | JUnit, Spring 테스트 도구 | 업무 규칙·권한·DB 처리 검증 |
| 빌드·이력 | Gradle Wrapper, Git / GitHub | 과거 프로젝트 경험 활용, 빌드 재현과 변경 관리 |
| 로컬 환경 | Docker Compose | PostgreSQL 개발 환경 재현 |
| DB 변경 관리 | Flyway (도입 예정) | 버전별 SQL로 스키마 변경 이력 관리 |
| CI | GitHub Actions (도입 예정) | PR의 빌드·자동 테스트 |
| 배포 | Linux 기반 환경, 제공업체 미정 | HTTPS, 로그, 백업·복구 |

버전과 의존성 조합은 프로젝트 생성 시 지원 상태와 호환성을 확인하여 고정합니다.

## 기술 선택 이유

- Spring Boot + Spring MVC + Thymeleaf: 하나의 애플리케이션에서 요청, Java 처리, DB 조회, HTML 표시를 연결합니다.
- MyBatis: 테이블 관계와 SQL을 직접 설계하고, 조회 결과가 Java 객체로 매핑되는 과정을 학습합니다.
- PostgreSQL: 기존 학습 경험을 활용하고 개발·통합 테스트·운영에서 동일한 DB 계열을 사용합니다.
- 세션 인증: 동일 사이트의 관리자 로그인 요구에 맞추어 구성합니다.
- Gradle: 이전 Fukuoka Guide 프로젝트에서 사용한 도구를 이어갑니다. 초기 제안의 Maven을 변경한 이유입니다.
- 단일 애플리케이션: 기능별로 코드를 나누되 하나의 배포 단위로 운영합니다.

Spring MVC는 JSON API에도 사용할 수 있습니다. 이번 프로젝트는 HTML 응답 중심으로 시작하고 필요할 때 JSON API를 추가합니다.
안정적인 기술 선택은 지원 종료 버전을 사용하는 것을 의미하지 않습니다. 배포 전 보안 업데이트와 의존성 호환성을 확인합니다.

## 설계 방향

- Controller: 요청·입력 검증 결과 처리, Service 호출, 화면 선택
- Service: 업무 규칙과 트랜잭션 경계
- Mapper: SQL 실행과 데이터 매핑
- View: Thymeleaf를 통한 HTML 표시
- 공개 조회에는 공개 상태 조건을 일관되게 적용합니다.
- 글과 태그 연결처럼 함께 성공해야 하는 DB 변경은 하나의 트랜잭션으로 처리합니다.
- 파일 저장은 DB 트랜잭션과 별개이므로 실패 시 정리 절차를 설계합니다.

## 예정 프로젝트 구성

프로젝트 생성 시 아래 경로를 기준으로 구성합니다. 현재는 문서만 존재합니다.

| 경로 | 역할 |
| --- | --- |
| `src/main/java/dev/sung/tokyolifeblog/` | 애플리케이션 코드 루트(제안) |
| `.../post/`, `.../category/`, `.../auth/`, `.../image/` | 기능별 Controller·Service·Mapper·DTO |
| `.../common/`, `.../config/` | 공통 오류 처리와 설정 |
| `src/main/resources/templates/` | 방문자·관리자 Thymeleaf 화면 |
| `src/main/resources/static/` | CSS·JavaScript·고정 이미지 |
| `src/main/resources/mapper/` | MyBatis SQL XML |
| `src/main/resources/db/migration/` | DB 변경 SQL |
| `src/test/` | 업무 규칙·웹·DB 통합 테스트 |
| `compose.yaml` | 로컬 DB 구성: 저장소 루트에 배치 예정 |
| `.github/workflows/` | CI 설정 |
| `docs/` | 요건·설계·테스트·운영 문서 |

운영자가 업로드한 사진은 소스 코드나 컨테이너 내부 임시 공간에 보관하지 않습니다. 영속 저장소를 사용하고 DB에는 참조 정보를 저장합니다.

## 실행 및 테스트

아직 애플리케이션 코드가 없습니다. 개발 환경 구성 후 필수 도구, DB 초기화 방법, 환경변수, 실행·테스트 명령을 추가합니다.
배포 주소와 화면 이미지는 실제 배포 후 추가합니다.

## 작업 방식

- Issue에 목적과 완료 조건을 작성하고 기능 단위로 작업합니다.
- 작업 브랜치에서 변경 후 PR에 변경 이유와 검증 결과를 기록합니다.
- 구현 완료와 예정 기능을 구분하고 문서를 코드와 함께 갱신합니다.
- 비밀번호·API 키·실제 개인정보는 저장소에 커밋하지 않습니다.

## 배포·운영 계획

1. 글 목록·상세가 동작하면 제한된 테스트 환경에 먼저 배포하여 DB 연결과 재시작을 확인합니다.
2. 핵심 기능과 권한 테스트를 완료한 뒤 HTTPS로 공개합니다.
3. 첫 배포 절차를 기록한 후 반복 작업을 자동화합니다.
4. DB와 이미지의 영속 저장·외부 백업·복구를 검증하고 오류 로그와 서비스 상태를 확인합니다.
5. 실제 글을 게시하고 발견한 문제를 Issue로 기록하여 수정·재배포합니다.

제공업체·요금제·도메인은 예산 확인 후 결정합니다. 초기 구성은 Linux 서버 한 대에서 앱·DB를 운영하는 방안을 후보로 두며, 장애 시 함께 중단될 수 있어 서버 외부 백업이 필요합니다.
